# Module 7.6: auth requirements

Purpose: ask the payer to rule on the quoted procedure set before the pre-auth: which lines are authorised, which excluded, which documents and forms are due at which leg. Asked, never awaited.

Skills: `nhcx-preauth`. It extends the 7.4 builder with items; it never writes a second.

## Depends on

7.1 to 7.5.

## Inputs

- `nhcx-build/mapping.json` `tables.claim_auth*`
- `references/fhir-knowledge.md` section 3 (the auth-requirements reader)
- `references/flow-knowledge.md` section 5 ("The auth-requirements check is asked, never awaited")
- Pin: `nhcx-package/fhir/B1/auth-requirements.json`
- Payer rulings: `nhcx-package/fhir/C3/C3-response-pmjay.json` (PMJAY: documents by stage and forms by `fullUrl`) and `nhcx-package/fhir/C3/C3-response-generic.json` (generic payer). The shape is in `nhcx-package/docs/05-FHIR Reference/03-Coverage Eligibility Response.md`. The PMJAY sandbox rarely answers this leg.

## Build

### The builder

The same coverage request builder from 7.4 with purpose `auth-requirements` and `item[]` from the quoted lines: `category` (specialty), `productOrService` (package), `quantity.value` as an integer, each tier as a `modifier` coding with code and display and no system.

### The fingerprint

`procedure_set(claim_id) -> str`: a stable hash of the quoted codes, kinds, quantities and parents. `ensure_auth_requirements(claim_id)` sends only when no `claim_auth` row exists for the current fingerprint. An unchanged set is never asked twice.

### The send

From the pre-auth screen's "validate" action and, silently, before a pre-auth submit. The submit does not wait for the answer: the PMJAY sandbox rarely sends one. Status `checking` with the three exchange ids on the `claim_auth` row.

### The reader

`parse_auth_bundle(bundle)`: one `insurance[0].item` per quoted line with `authorizationRequired`, `excluded`, `benefit[0]`, `authorizationSupporting[]`. Each supporting entry is a CodeableConcept whose `text` the scheme overloads: `fullUrl: <questionnaire url>` marks a form; `Type: pre` or `Type: post` says the leg a document is due at; `Procedure Code: X` names the line. Store one `claim_auth_item` per line and one `claim_auth_requirement` per document or form with `kind`, `code`, `url`, `stage`, and `at_preauth` (a form is always wanted at pre-auth; a document only when its stage is `pre`).

### What the ruling changes

7.7 reads the ruling first: with one, the forms and documents it names for the leg; without one, the plan's list for the quoted packages (7.5). The ruling never changes the lines themselves; an `excluded` line is shown as such and left for the desk.

## Rules

- Quantity is an integer on the wire.
- Never block the pre-auth on this answer.
- The payer adapter (7.11) says whether a payer answers this leg at all (`auth_requirements` flag); a payer that does not is not asked.

## Pseudo code

Builder and reader: `fhir/FHIR.md` section 2 (`auth-requirements` purpose, `parse_auth_bundle`). Orchestration:

```
function procedure_set(claim_id):
    lines = sorted(lines(claim_id), key = (kind, code, parent_code))
    return sha256("|".join(f"{l.kind}:{l.code}:{l.quantity}:{l.parent_code}" for l in lines))[:16]

function ensure_auth_requirements(claim_id):                     # called by the "validate" action and silently before submit_preauth
    row = claim(claim_id); adapter = payers.for_claim(row)
    if not adapter.auth_requirements or not lines(claim_id): return false
    fp = procedure_set(claim_id)
    if select_one("claim_auth", where = {claim_id, fingerprint: fp}): return false      # unchanged set: never asked twice
    auth = insert("claim_auth", {claim_id, fingerprint: fp, status: "checking"})
    items = [{"category": {code: l.category_code, display: l.category_display}, "code": l.code, "display": l.display, "quantity": int(l.quantity),
              "tiers": [{code: t.code, display: t.display} for t in tiers_of(claim_id, l.code)]} for l in package_lines(claim_id)]
    bundle = fhir.build_coverage_request({purpose: "auth-requirements", member_id: row.member_id, policy_code: row.policy_code, facility: settings.facility,
                                          payer: payer_of(row), created: now_ist(), items})
    r = transport.send("v1/coverageeligibility/check", bundle, recipient_of(row), workflow_id = row.claim_no, claim_no = row.claim_no, usecase = "auth-requirements")
    update(auth, {txn_id: r.txn_id, correlation_id: r.correlation_id, api_call_id: r.api_call_id, request_json: bundle, sent_at: now()})
    return true                                                  # the caller does not wait

APPLY["claim_auth"] = function (auth, env):
    p = fhir.parse_auth_bundle(env.fhir)
    for i in p.items: insert("claim_auth_item", {auth_id: auth.id, code: i.code, authorised: i.authorised, excluded: i.excluded, benefit_json: i.benefit})
    for r in p.requirements: insert("claim_auth_requirement", {auth_id: auth.id, line_code: r.line, kind: r.kind, code: r.code, display: r.display, url: r.url, stage: r.stage, at_preauth: r.at_preauth})
    update(auth, {status: "ready", response_json: env.fhir, answered_at: now()})
```
