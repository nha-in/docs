# Module 7.7: the Claim bundle

Purpose: one builder for every leg that carries a `Claim`: pre-auth 12, enhancement 13, query answers 19 and 131, claim 15, claim query answer 161, predetermination. The heaviest bundle and the one PMJAY refuses most. Five pins hold it.

Skills: `nhcx-preauth` (pre-auth 12, enhancement 13, query answers 19 and 131, predetermination) and `nhcx-claim` (claim 15, query answers 161 and 151, resubmit 16). One builder: the second skill extends it, and stage 8 re-runs the first skill's pin comparisons.

## Depends on

7.1 to 7.6.

## Build

### The builder

`claim_bundle(leg, use, data) -> bundle` with `leg` in `preauth`, `claim`, `predetermination`, `flow` in `request`, `enhancement`, `queryupdate` (carried in `data`), and `use` in `preauthorization`, `claim`, `predetermination`. Pure: `data` holds everything, the builder touches no table. Entries in the pinned order: Claim, Patient, provider Organization, payer Organization, Coverage, Practitioner (one per care team member), Procedure (one per package), QuestionnaireResponse (one per answered form).

### The Claim

- `id` and the `CLN` identifier = the claim number. On the claim leg, the pre-auth's number (ERR-PYR-CLM-007).
- Element ids on every indexed list: `item[].id = Item/n`, `procedure[].id = Procedure/n`, `supportingInfo[].id = SupportingInformation/n`, and `sequence` on every `supportingInfo` entry, numbered once after the list is assembled (PAYR-1019, PAYR-1027).
- `type` SNOMED `737481003`, `use`, `billablePeriod`, `created`, `insurer`, `provider`, `priority normal`.
- `careTeam[]`: `primary` first, `assist` after, each pointing at a Practitioner that carries the `HPIN` identifier under `https://hpr.abdm.gov.in` (PAYR-1083), plus `HPID` and `MD` when known, and a `qualification.code` from HL7 v2-0360.
- `diagnosis[]`: ICD-10 with display, type `admitting`, `onAdmission yes`.
- `procedure[]`: `type` = the plan's `ProcedureType` condition lower-cased, `date`, `procedureReference`.
- `insurance[0]`: `focal true`, `coverage`, and on the claim `preAuthRef` = the payer's `ClaimResponse.preAuthRef` from 7.8.
- `item[]`: one per procedure or implant, never per tier. `modifier[]` one coding per tier. `programCode AB-PMJAY` for PMJAY only. `unitPrice` = net divided by quantity; `factor` from the multiple-procedure rule (1, 0.5, 0.25 by cost rank; PMJAY only); `net` = the line plus its tiers. `total` = the sum of nets.

### supportingInfo

The table in `fhir-knowledge.md` section 5, exactly: one `INV` entry per document with the plan's code (else `ODN`, never dropped); `ONS/ADDD` and `OTH/EDT` on every leg; `HDS` with the plan's summary code, `ONS/PSP`, `ONS/DSDE`, `DIS` on the claim; `ONS/DTM` on death (PAYR-1096); `NMI/CQD` with the desk's reply on a query answer; one `INF` (or `STG`) `valueReference` per QuestionnaireResponse.

### Forms and documents that ride

`required_forms(claim_id, stage)`: with a ruling, the forms it named for the leg; without one, at pre-auth every guideline form the plan attaches to the quoted packages; on both legs every policy-level form (the consent form: PAYR-1256 at pre-auth, PAYR-1363 at claim; STG: PAYR-1254, PAYR-1365). `required_documents(claim_id, stage)`: the ruling's list, else the plan's for the quoted packages at pre-auth and what was not attached there at the claim. A file attached against a requirement carries its code. Content types: pdf, jpg, jpeg, png only.

### The legs

| Leg | flow | use | Procedure status | Extra |
| --- | --- | --- | --- | --- |
| Pre-auth 12 | `request` | `preauthorization` | `preparation` | |
| Enhancement 13 | `enhancement` | `preauthorization` | `preparation` | every line old and new under the same number; costlier at factor 1, the other at 0.5 |
| Query answer 19, 131 | `queryupdate` | `preauthorization` | `preparation` | `NMI/CQD` |
| Claim 15 | `request` | `claim` | `completed` | discharge scalars, summary, `preAuthRef`, the pre-auth's number |
| Claim query answer 161 | `queryupdate` | `claim` | `completed` | as claim plus `NMI/CQD` |
| Predetermination | `request` | `predetermination` | `preparation` | on `v1/preauth/submit`, workflow 12 |

LAMA or DAMA before or during surgery: the claim carries one item, `LM100` at the plan's rate, no tier, and nothing else (PAYR-1362). After surgery the package stands. `LM100` never rides a pre-auth (PAYR-1270).

### The senders

`submit_preauth(claim_id, reply)` picks the send kind (`preauth_send_kind`: a fresh 12 after a rejection, never 121; 19 when a query is open on a `resubmit` payer; 13 when lines were added after approval; 131 for a queried enhancement), builds, sends through 7.1 with the kind's workflow id from 7.11, stores the three ids and `submission_kind` and `workflow_id`, keeps `thread_correlation_id`, status `submitting`. `submit_claim(claim_id, reply)` the same for 15 and 161 (`claim_send_kind`; PMJAY has no 16, a decided claim is reprocessed).

## Rules

- Never hard-code a document code, package code, questionnaire url or summary code.
- The desk's query reply goes on `NMI/CQD`, on a fresh correlation id for a `resubmit` payer. A same-thread answer is swallowed.
- One live pre-auth per beneficiary per hospital (PAYR-1238) and one request at a time per case (PAYR-1322) are scheme rules; the sender surfaces the refusal, it does not retry blindly.

- [ ] Every reference resolves to a `fullUrl` in the bundle.
- [ ] Every `item`, `procedure` and `supportingInfo` entry has an `id`; every `supportingInfo` has a `sequence`, contiguous from 1.
- [ ] Every Practitioner has an `HPIN` identifier under `https://hpr.abdm.gov.in`.
- [ ] `total.value` equals the sum of `item[].net.value`; tiers appear only as `modifier`.
- [ ] A death claim carries `ONS/DTM`; a LAMA-before-surgery claim carries only `LM100`.
- [ ] The claim leg's `Claim.id` equals the pre-auth's claim number and `insurance[0].preAuthRef` is the payer's reference.
- [ ] After a rejection, `preauth_send_kind` yields `preauth` (12), not `preauth_resubmit` (121).
- [ ] No string literal in the module matches `MAND\d+`, `MG\d+`, or `/questionnaire/` (grep).

## Pseudo code

The builder, the supportingInfo table, the forms and documents that ride, and the LAMA collapse: `fhir/FHIR.md` section 4. The senders:

```
function preauth_send_kind(claim_id):
    pa = preauth(claim_id)
    if not pa or pa.status in ("draft", "error", "rejected", "cancelled"): return "preauth"          # a fresh 12 after a rejection; never 121
    if pa.status == "queried": return "enhancement_resubmit" if pa.submission_kind in ("enhancement", "enhancement_resubmit") else "preauth_query_response"
    if pa.status in ("approved", "partial") and enhancement_lines(claim_id): return "enhancement"
    return null                                                  # nothing to send

function submit_preauth(claim_id, reply = null):
    row = claim(claim_id); adapter = payers.for_claim(row); kind = preauth_send_kind(claim_id)
    if not kind: raise "nothing to send"
    if kind in ("preauth_query_response", "enhancement_resubmit") and adapter.query_mode != "resubmit": raise "answer this payer on the inbox"
    ensure_auth_requirements(claim_id)                           # asked, not awaited
    flow = {"preauth": "request", "enhancement": "enhancement", "preauth_query_response": "queryupdate", "enhancement_resubmit": "queryupdate"}[kind]
    d = claim_inputs(claim_id, flow = flow, stage = "preauth", query_reply = reply)    # tables -> the data dictionary; no DB inside the builder
    bundle = fhir.claim_bundle("preauth", "preauthorization", d)
    pa = preauth(claim_id) or insert("claim_preauth", {claim_id, claim_ref: row.claim_no})
    update(pa, {status: "submitting", submission_kind: kind, workflow_id: adapter.workflow_ids[kind], request_json: bundle, error_message: null})
    try:
        r = transport.send("v1/preauth/submit", bundle, recipient_of(row), workflow_id = adapter.workflow_ids[kind], claim_no = row.claim_no, usecase = kind)
        update(pa, {txn_id: r.txn_id, correlation_id: r.correlation_id, api_call_id: r.api_call_id, sent_at: now()})   # thread_correlation_id untouched until the payer answers
    except TransportError as e:
        apply_door_refusal(("claim_preauth", pa), e)              # restores status and the thread
    stamp_case(claim_id)

function claim_send_kind(claim_id):
    cs = submission(claim_id); adapter = payers.for_claim(claim(claim_id))
    if not cs or cs.status in ("draft", "error"): return "claim"
    if cs.status == "queried": return "claim_query_response"
    if cs.status == "rejected" and adapter.workflow_ids.get("claim_resubmit"): return "claim_resubmit"   # generic only; PMJAY reprocesses
    return null

function submit_claim(claim_id, reply = null):
    row = claim(claim_id); pa = preauth(claim_id); adapter = payers.for_claim(row); kind = claim_send_kind(claim_id)
    if not pa or pa.status not in ("approved", "partial"): raise "no approved pre-authorisation"
    if not submission(claim_id).discharge_mode: raise "record the discharge first"
    d = claim_inputs(claim_id, flow = "queryupdate" if kind == "claim_query_response" else "request", stage = "claim", query_reply = reply)
    d.claim_no = pa.claim_ref or row.claim_no                    # under the pre-auth's number: ERR-PYR-CLM-007
    d.preauth_ref = pa.preauth_ref; d.lines = fhir.lines_for(case, "claim")     # LM100 collapse
    bundle = fhir.claim_bundle("claim", "claim", d)
    ... same send pattern on "v1/claim/submit" with adapter.workflow_ids[kind] ...

function claim_inputs(claim_id, flow, stage, query_reply):
    row = claim(claim_id); enc = encounter(row.encounter_id); pat = patient(row.patient_id)
    return {flow, claim_no: row.claim_no, created: now_ist(),
            admission: {admitted_at: enc.admitted_at, discharged_at: enc.discharged_at, surgery_at: enc.surgery_at, death_at: enc.death_at, mode: enc.discharge_mode, stage: enc.discharge_stage},
            patient: {member_id: row.member_id, abha: pat.abha, name: pat.name, phone: pat.phone, gender: pat.gender, birthDate: pat.dob},
            facility: settings.facility, payer: payer_of(row), policy_code: row.policy_code,
            care_team: [{hpin: d.hpr_id, hpid: d.hpr_id, licence: d.licence, name: d.name, qualification_code: degree_code(d.qualification), ...} for d in care_team(claim_id)],
            diagnoses: diagnoses(claim_id), lines: lines(claim_id),
            documents: [doc_with_bytes(x) for x in required_documents_attached(claim_id, stage)],
            forms: answered_forms(claim_id, stage), program_code: payers.for_claim(row).program_code, factor_rule: "pmjay" if program_code else null,
            summary: discharge_summary(claim_id) if stage == "claim" else null, query_reply}
```
