# UHI atoms (2026-09-29)

**Why.** UHI shipped its specification, journeys and pages on 29 September 2026 with no atoms, so the Docs MCP and Ask AI answer UHI questions from HIE-CM and NHCX atoms, and no UHI claim can be cited by id.

**Goal.** UHI carries atoms in the page-canonical structure (`2026-09-28-page-canonical-knowledge-atoms.md`), built the way the HIE-CM rebuild built its own (`2026-09-29-hiecm-atoms-rebuild.md`): every atom is a page section with an explicit heading id and a map entry in `catalogue/map.d/uhi-*.yaml`, agent-only rules sit in `<AgentOnly>` on the same page, and `catalogue/generated/uhi/**` is built from them.

**Base.** Branch `feat/uhi-atoms`, stacked on `feat/docs-mcp-retrieval` (contract v2, `map.d`, the retrieval gate), with `feat/uhi-reference` merged in for the UHI pages, specifications and journeys.

**Sources.** Only the UHI set under `catalogue/openapi/.raw/nha-2026-09-28-uhi/`: the developer guide of 22 September 2026, the Gateway spec v2.0.2 as ingested into `catalogue/openapi/uhi/v1/`, and the onboarding documents where those two are silent. `catalogue/openapi/corrections/2026-09-28-uhi-sources.md` settles every conflict. Nothing else.

## Rules for every atom

1. `gateway: uhi`, `milestone: n/a` (milestone stays HIE-CM only), `version: uhi-v1`. Endpoint and callback atoms carry `operation`. No `side`: its values are HIE-CM and NHCX roles.
2. An id is `uhi.<type>.<slug>`, fixed by the inventory below so batches can cite each other in `related`.
3. A section's heading id keeps the anchor the page already publishes when that anchor is `[a-z0-9-]+`, so no link breaks. When it cannot (an underscore, a colon), the new id is used and every link to the old anchor under `site/`, `catalogue/`, `skills-src/` and `plugins/` is updated in the same batch.
4. Visible text follows `page-authoring`, `nha-voice` and `writing-guide`: written as ABDM, no em dash, no attribution. Existing page prose is kept; a section gains an id and, where an agent needs more than the page says, a labelled `<AgentOnly>` block (`**Before you start.**`, `**What happens.**`, `**How you know it worked.**`, `**When it goes wrong.**`).
5. An `<AgentOnly>` note never states a backticked literal that neither its page nor a UHI specification states. `check:sections` fails it.
6. A `.md` page is converted to `.mdx` only when it gains an `<AgentOnly>`, as its own step, followed by a site build with no errors.
7. `related` names only ids in this inventory or atoms that already exist.
8. The gate per batch: `check:sections`, `lint:atoms`, `lint:content`, `test:scripts`, the site build, and the retrieval gate before and after. No case may fall.
