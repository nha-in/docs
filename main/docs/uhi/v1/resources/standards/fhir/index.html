FHIR records and profiles

Every ABDM health record and claim is a FHIR R4 bundle that conforms to the ABDM FHIR implementation guide. This page gives the guide, the code systems its profiles bind, and how to validate a bundle against it.

In short​

  • Every ABDM record and claim conforms to the ABDM FHIR implementation guide, version 6.5.0 on FHIR 4.0.1.
  • Coded fields take SNOMED CT, LOINC, ICD-10 or the guide's own code systems, each by a fixed URI.
  • Validate every bundle against ndhm.in#6.5.0 before you send it.

The ABDM FHIR implementation guide​

The ABDM FHIR implementation guide is the set of FHIR R4 profiles every ABDM health record and claim conforms to. Base FHIR says a resource exists. The guide says which fields an Indian record must fill, and which code systems those fields take.

The guide is published by the National Resource Centre for EHR Standards, NRCeS, at nrces.in/ndhm/fhir/r4.

FieldValue
Current version6.5.0, published 8 May 2025
FHIR version4.0.1
Package idndhm.in#6.5.0
Canonical URLhttps://nrces.in/ndhm/fhir/r4/ImplementationGuide/ndhm.in
LicenceFHIR is free to use, redistribute and build on. See HL7 FHIR at NRCeS.

What the guide holds​

SectionWhat you find there
ProfilesThe health record profiles: OP consultation, prescription, diagnostic report, discharge summary, immunisation, wellness, health document and invoice
NHCX profilesThe claim, coverage eligibility, insurance plan, communication and payment profiles for health claims
TerminologyThe guide's own code systems and value sets
ExamplesA worked example for every profile, in JSON and XML
Downloadspackage.tgz, the definitions and the examples as zip files
HistoryEvery published version, from 1.0.0 in August 2020

Pin the version you build against. Read the history before you move to a newer one.

The code systems it binds​

A coded field names its code system by URI. The URI is an identifier, not a web address: send it exactly as the profile fixes it, in the coding's system.

Code systemSystem URIWhere the guide uses it
SNOMED CThttp://snomed.info/sctRecord types, conditions, procedures, allergies, medicines, specimens and most clinical codes
LOINChttp://loinc.orgLaboratory and imaging report codes, and vital sign and body measurement observations
ICD-10http://hl7.org/fhir/sid/icd-10Diagnoses on Condition, and on claims
Guide code systemshttps://nrces.in/ndhm/fhir/r4/CodeSystem/...Administrative and claim codes, such as identifier types and billing codes

Quantities in the guide's examples carry units from http://unitsofmeasure.org. See an Observation example.

Validate a bundle against it​

The Implementation Guide for Adoption of FHIR in ABDM and NHCX gives three ways to validate.

WayHow
Command linejava -jar validator_cli.jar <file_name> -ig ndhm.in#6.5.0
BrowserOpen validator.fhir.org and select the ndhm.in guide
In your codeLoad package.tgz into the HAPI FHIR validator from your classpath

The validator checks structure, profile conformance and coding. Every coding must carry the correct system URL, code and display.

Tools and samples​

  • ABDM FHIR R4 usage samples in Java and in .NET, which build bundles in code.
  • The NRCeS terminology server, which supports $lookup, $validate-code and $translate.
  • Tools and technologies, the full list of NRCeS tools.

How you know it worked​

The validator reports no errors for your bundle against ndhm.in#6.5.0.

When it goes wrong​

  • A coding fails validation. The system URI differs from the one the profile fixes. Copy it from the profile, not from an older sample.
  • Anything else. Read the FHIR questions in the NRCeS FAQ.
