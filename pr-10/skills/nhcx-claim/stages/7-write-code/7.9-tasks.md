# Module 7.9: Tasks

Purpose: the small exchanges on `v1/task/submit`: cancel a pre-auth (PC01), reprocess a decided claim (36), release a shortfall (36), enquire status; and read their answers (PC02, 37, the status Task).

Skills: `nhcx-preauth` (cancel PC01 and its PC02) and `nhcx-reprocess` (reprocess and release on 36, status, and their answers). One Task builder for all four.

## Depends on

7.1 to 7.3, 7.7, 7.8.

## Inputs

- `references/fhir-knowledge.md` sections 7 and 8
- `references/flow-knowledge.md` section 2 (`cancel`, `reprocess`, `release`, status rows) and section 5 ("Cancel retires the number")
- `references/errors-and-debugging.md` section 2 (PAYR-1008 on Tasks, PAYR-1018)
- Pins: `nhcx-package/fhir/B3/preauth-cancel.json`, `nhcx-package/fhir/B5/claim-reprocess.json`, `B5/claim-release.json`; answers: `nhcx-package/fhir/C10/C10-cancelled-wfPC02.json` and `C10/C10-arbitration-wf37.json`, each with a `-pmjay` twin. No answer to a status Task is published.

## Build

### The builders

A TaskBundle with the Task at `https://nhcx.abdm.gov.in/<leg>/<action>` followed by the provider and payer Organizations. The Task: `status requested`, `intent order`, `code` on the HL7 financial task code system with no display, `description`, `authoredOn`, `requester` the provider, `owner` the payer, `basedOn` the Claim by identifier.

| Task | code | reason | inputs | Workflow |
| --- | --- | --- | --- | --- |
| Cancel | `cancel` | `treatmentplanchanged` or the desk's | `claimNumber`, `intimationNumber` | `PC01` (override to 122 per payer if insisted) |
| Reprocess | `reprocess` | the desk's | `intimationNumber` (that spelling; any other is refused with PAYR-1008), the reason text, document attachments | `36` |
| Release | `release` | `partialpayment` | `claimNumber`, `amount` as `valueMoney` | `36` |
| Status | `status` | none | `claimNumber` | the leg's correlation id, fallback `13` |

### The senders

Each creates a `claim_enquiry` row (or the cancel fields on `claim_preauth`) with the three exchange ids on its own thread, and sends through 7.1. Status is offered only to a payer whose adapter (7.11) allows it; PMJAY refuses it with PAYR-1018 and the screen must not offer it.

### The readers

- PC02 (`task/on_submit`): the pre-auth becomes `cancelled`; the episode gets a fresh claim number and the withdrawn number stays on the leg. A ProtocolResponse instead leaves the pre-auth as it was, with the payer's words in the cancel error.
- 37: the enquiry row `answered`; a fresh verdict on the claim's own thread follows and 7.8 reads it.
- The status Task's answer: `claimStatus` output onto the enquiry row; the leg unchanged.

## Rules

- On the PMJAY sandbox only `cancel` is accepted; `status`, `reprocess` and `release` come back PAYR-1008 or PAYR-1018. Record the refusal on the enquiry row with the payer's words; nothing else changes.
- A decided PMJAY claim goes back only as a reprocess; there is no 16.

## Pseudo code

Builders and the Task reader: `fhir/FHIR.md` section 6. Senders:

```
function cancel_preauth(claim_id, reason_code, reason_text):
    row = claim(claim_id); pa = preauth(claim_id); adapter = payers.for_claim(row)
    if pa.status in ("rejected", "cancelled", "draft"): raise "nothing to cancel"
    if submission(claim_id) and submission(claim_id).status != "draft": raise "a claim has been raised"
    bundle = fhir.cancel_task(pa.claim_ref, {code: reason_code, display: reason_display(reason_code)}, now_ist(), settings.facility, payer_of(row))
    update(pa, {cancel_status: "cancelling"})
    r = transport.send("v1/task/submit", bundle, recipient_of(row), workflow_id = adapter.workflow_ids.cancel, claim_no = row.claim_no, usecase = "cancel")
    update(pa, {cancel_txn_id: r.txn_id, cancel_correlation_id: r.correlation_id, cancel_api_call_id: r.api_call_id}); stamp_case(claim_id)

function ask_reprocess(claim_id, reason_code, description, document_ids):
    row = claim(claim_id); cs = submission(claim_id); adapter = payers.for_claim(row)
    e = insert("claim_enquiry", {claim_id, kind: "reprocess", stage: "claim", reason_code, document_ids, status: "submitting"})
    bundle = fhir.reprocess_task(cs.claim_ref, row.member_id, {code: reason_code, display: ...}, description, [doc_with_bytes(i) for i in document_ids], now_ist(), settings.facility, payer_of(row))
    r = transport.send("v1/task/submit", bundle, recipient_of(row), workflow_id = adapter.workflow_ids.reprocess, ...)
    update(e, {txn_id: r.txn_id, correlation_id: r.correlation_id, api_call_id: r.api_call_id, request_json: bundle})

function ask_release(claim_id, amount):  same with fhir.release_task(..., amount, ...), kind "release"
function ask_status(claim_id, stage):
    if not payers.for_claim(claim(claim_id)).status_enquiry: raise "this payer refuses status enquiries"     # PMJAY: PAYR-1018
    leg = preauth(claim_id) if stage == "preauth" else submission(claim_id)
    ... fhir.status_task(...) sent with workflow_id = leg.correlation_id or "13", kind "status"

APPLY["claim_preauth" on cancel_correlation_id] = function (pa, env):     # PC02
    t = fhir.parse_task_answer(env.fhir); row = claim(pa.claim_id)
    if t.status in ("completed", "accepted"):
        update(pa, {status: "cancelled", cancel_status: "cancelled"})
        update(row, {claim_no: next_claim_no()})                 # the number is retired; pa.claim_ref keeps the old one
    else: update(pa, {cancel_status: "error", cancel_error: t.description})

APPLY["claim_enquiry"] = function (e, env):
    t = fhir.parse_task_answer(env.fhir)
    update(e, {status: "answered", answer: t.claim_status or t.description, response_json: env.fhir, answered_at: now()})
    if e.kind in ("reprocess", "release"): update(submission(e.claim_id), {status: "submitting"})     # a fresh verdict follows on the claim's thread
```
