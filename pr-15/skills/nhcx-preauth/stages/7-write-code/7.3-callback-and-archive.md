# Module 7.3: the callback door

Purpose: the one path every message arrives by. The transport's receiving end answers the sender and hands on one envelope; the door dedupes, archives, matches, applies and stamps. Also the poll fallback, where the transport has something to poll.

Skills: the foundation (`core/FOUNDATION.md`). Built whole by the first skill whose stage 0 finds it absent; every skill wires its own readers into `APPLY` and tests the door refusal on its own thread.

## Build

### The receiving end, per transport

| Kind | Route | Answers the sender | Hands the door |
| --- | --- | --- | --- |
| `own` | `POST /v1/<path>` under the registered `endpoint_url`: every path in `transport-knowledge.md` section 3.9, `/v1/error` included. Exempt from session auth and CSRF; reachable from the exchange's addresses | `202` with the receipt, within 30 seconds, for every delivery | The opened JWE's header and bundle as `fhir`; a ProtocolResponse as `protocol`; the `/v1/error` report as `error` |
| `existing` | The app's own callback | As the app already does, if that meets section 3.9; else extended until it does | What the app's handler holds after its receipt, mapped onto the envelope |
| `adapter` | `/nhcx/callback` and `/nhcx/callback/<any path>`, because the adapter appends the NHCX path. Exempt from session auth and CSRF; the shared secret from `Authorization: Bearer` when configured, else 401 | Any 2xx; the adapter then sends the receipt | The adapter's `{meta, jwe_headers, fhir}` as it arrives |

A body the transport cannot read (not JSON, no payload, a JWE that will not open) is archived under `unmatched` and changes nothing. With `adapter`, answer 400: redelivery cannot fix it. With `own`, answer 202 with the receipt's `error` filled, because the exchange reads anything else as a failed delivery and redelivers.

### The door: `receive(envelope)`, in order

1. The envelope is `{meta: {path, payloadType, redelivery}, jwe_headers, fhir}` from the receiving end.
2. Read `x-hcx-api_call_id` from `jwe_headers`. If a row anywhere already holds this api call id, archive under the case as `-redelivered`, return `ignored`, and stop. Nothing changes.
3. Archive the envelope under the matched case (or under `unmatched` until matched), as `NNN-<usecase>-in.json` plus a `transactions.txt` line. Archive before applying, so a crash mid-apply leaves evidence.
4. Match. `x-hcx-correlation_id` against every leg table's `correlation_id` (and `thread_correlation_id`), in a fixed order; then the claim number inside the bundle (`ClaimResponse.identifier[0].value`, `Task.input` `claimNumber`, `PaymentNotice.request` identifier); then unmatched. Route by correlation id, never by the path the message arrived on; `meta.path` says only the entity.
5. Apply. Dispatch on the matched leg's kind to the reader in 7.4 to 7.10. For `payloadType` `protocol` (a ProtocolResponse), apply the door-refusal rule instead: the leg's status becomes `error` with the payer's `x-hcx-error_details` text, and `correlation_id` is restored from `thread_correlation_id`. For a query answer refused at the door, restore `queried`; for an enhancement refused, restore `approved`. For `payloadType` `error` (a `/v1/error` report), show it on the case it names by any correlation id or claim number it carries, else keep it under `unmatched`; nothing else changes.
6. Stamp stage and sub-stage (7.11).
7. Return `settled`, `unmatched` or `ignored`. The receiving end answers the sender: the receipt for `own`, a 200 with `{"status": ...}` for `adapter`. An unexpected exception after step 3 becomes a 500, so the sender redelivers; the archive already holds the message.

Do slow work after answering where the framework allows it (a detached task, a queue). Where it does not, keep the apply fast: no outbound sends inside the door, no validator calls (the validator is run offline, as `references/fhir-knowledge.md` section 11 describes). The exchange allows 30 seconds for the receipt.

### The poll fallback

- `adapter`: one function per leg kind that, when a leg is `submitting` or `checking` and older than a threshold, calls 7.1's `fetch_missed` and feeds each fetched envelope to `receive`. It is called from the case screen's request path (no worker) or a scheduler (worker). A 404 from `txn/related` settles the leg as an error.
- `own`, and `existing` without a store of inbound messages: there is nothing to poll. A leg with no answer stays waiting and the page shows for how long; `/v1/error` and the status exchange (`transport-knowledge.md` section 3.10) are how a lost message surfaces. Never turn a quiet leg into an error on a timer.

### Inbound requests that are not answers

`v1/communication/request` and `v1/paymentnotice/request` arrive on new threads. They match by the claim number inside the bundle (step 4, second rule), create their own row (`claim_query`, `claim_payment`) keyed on the message's correlation id, and are answered later by 7.10. A second delivery of the same request hits the unique constraint from 7.2 and is treated as `ignored`.

## Rules

- Never close a thread on the first reply. Both live payers answer twice on one correlation id: `queued` first, the decision after.
- A message on an unknown correlation id is archived and answered (the 202 receipt for `own`, a 200 for `adapter`). Never 4xx it: NHCX redelivers five times and then retires the id.
- The door never sends. A notification acknowledgement or a payment acknowledgement is queued for 7.10 and sent outside the request, or sent by the desk's action; without a worker it is sent from the next request path.

## Validate

- [ ] Every inbound path reaches the handler: each `/v1/...` path in `transport-knowledge.md` section 3.9, `/v1/error` included (`own`); the callback base and the base plus `v1/preauth/on_submit` (`adapter`); the app's own routes (`existing`).
- [ ] A body the transport cannot read is archived and changes nothing: `adapter` answers 400; `own` answers 202 with the receipt's `error` filled.
- [ ] Two deliveries with one `x-hcx-api_call_id` produce one state change, and the second is `ignored`.
- [ ] A delivery on an unknown correlation id is answered (`own`: the 202 receipt; `adapter`: 200 `unmatched`) and archived under `unmatched`.
- [ ] A delivery is archived even when the apply step raises.
- [ ] A ProtocolResponse on a pre-auth thread sets the leg to `error` with the payer's words and restores `correlation_id` to `thread_correlation_id`.
- [ ] The handler makes no outbound HTTP call (assert with the 7.1 stub: zero sends during a delivery).
- [ ] Inbound authentication holds for the kind: with `adapter`, a delivery without the configured shared secret answers 401; with `own`, the NHCX JWT check runs when its key is configured, and a missing key is logged at start rather than skipped silently.

## Tests

Feed the payer answers in the package (`nhcx-package/fhir/C3` coverage, `C4` plan, `C5` pre-auth, `C6` communication, `C7` claim, `C9` payment, `C10` cancel and arbitration, `C11` predetermination) through `receive` as envelopes (`meta`, `jwe_headers` with a correlation id you set on a seeded leg, and `fhir`), then assert the leg's state. With `own`, also send each through the receiving end: seal it with a test key pair as the exchange would, POST it, assert the 202 receipt's fields and `entity_type`, then the leg's state. The cross-cutting rows of the test matrix (`references/testing-knowledge.md` section 3) are this module's tests: redelivery, unmatched, refusal at the door, ledger reset (`adapter` only), stage after every write.

## Pseudo code

The `own` receiving end (`POST /v1/<path>`: open, answer 202, call `receive`) is in `references/transport-knowledge.md` section 3.12. The `adapter` route and the door:

```
route POST /nhcx/callback and /nhcx/callback/<path:any>  (adapter only; exempt from session auth and CSRF)

function adapter_callback(request):
    if settings.adapter.callback_secret and request.headers.Authorization != "Bearer " + settings.adapter.callback_secret: return 401
    try: env = request.json()
    except: return 400, {"status": "bad-body"}
    if not (is_dict(env) and "jwe_headers" in env and "fhir" in env): return 400, {"status": "bad-body"}
    return 200, {"status": receive(env)}

function receive(env):
    h = env.jwe_headers; kind = env.meta.payloadType; path = env.meta.path
    if kind == "error":                                          # a /v1/error report: kept, shown, nothing else changes
        archive.record(claim_no_in_report(env.fhir), "error-report", "in", env); return "settled"
    api_call_id = h["x-hcx-api_call_id"]; cid = h["x-hcx-correlation_id"]
    if seen(api_call_id):                                        # any leg row or the archive index holds it
        archive.record(claim_no_for(cid), entity_of(path), "in-redelivered", env); return "ignored"
    match = match_thread(cid) or match_claim_number(env.fhir)   # (table, row) or null
    archived = archive.record(match.row.claim_no if match else null, entity_of(path), "in", env)   # BEFORE applying
    remember(api_call_id)
    if not match: return "unmatched"
    try:
        if kind == "protocol": apply_door_refusal(match, env)
        else: APPLY[match.table](match.row, env)                # 7.4 .. 7.10 readers
        stamp_case(match.row.claim_id)                          # 7.11
        archive.note(archived, "settled"); return "settled"
    except Exception as e:
        archive.note(archived, "error: " + str(e)); raise       # becomes a 500 and the sender redelivers; the archive holds the message

CORRELATION_TABLES = [("claim_preauth", "correlation_id"), ("claim_preauth", "thread_correlation_id"), ("claim_preauth", "cancel_correlation_id"),
                      ("claim_submission", "correlation_id"), ("claim_submission", "thread_correlation_id"),
                      ("claim_enquiry", "correlation_id"), ("claim_predetermination", "correlation_id"),
                      ("claim_plan", "correlation_id"), ("claim_auth", "correlation_id"), ("claim", "correlation_id"),
                      ("claim_query", "correlation_id"), ("claim_payment", "correlation_id")]

function match_thread(cid):
    for (table, column) in CORRELATION_TABLES:
        row = select_one(table, where = {column: cid})
        if row: return (table, row)
    return null

function match_claim_number(bundle):                            # inbound requests on new threads
    no = claim_no_in(bundle)                                     # ClaimResponse.identifier, Task.input claimNumber, PaymentNotice.identifier, CommunicationRequest.basedOn display
    if not no: return null
    row = select_one("claim", where = {"claim_no": no}) or select_one("claim_preauth", where = {"claim_ref": no})
    return ("inbound_request", row) if row else null            # APPLY["inbound_request"] dispatches on resourceType: PaymentNotice -> 7.10 record_payment, Task+CommunicationRequest -> 7.10 receive_communication

function apply_door_refusal(match, env):
    row = match.row; words = env.fhir["x-hcx-error_details"] or env.fhir.error
    if row.submission_kind in ("preauth_query_response", "claim_query_response"): row.status = "queried"
    elif row.submission_kind == "enhancement": row.status = "approved"
    else: row.status = "error"
    row.error_message = f"{words.code}: {words.message}"
    row.correlation_id = row.thread_correlation_id or row.correlation_id   # back to the thread the payer last answered on
    save(row)

function poll_missed(row):                                      # adapter only; request path or worker; never inside receive()
    if settings.transport != "adapter": return                  # own and existing: a quiet leg stays waiting
    if row.status not in ("submitting", "checking") or age(row.sent_at) < 20s: return
    result = transport.fetch_missed(row.txn_id)
    if result == LEDGER_RESET: row.status = "error"; row.error_message = "ledger reset; send again"; save(row); return
    for env in result: receive(env)                             # same path, same dedupe
```
