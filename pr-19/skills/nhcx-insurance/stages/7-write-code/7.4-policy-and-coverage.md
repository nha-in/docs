# Module 7.4: policy search and coverage eligibility

Purpose: find the beneficiary's policy, then ask the payer whether it is in force. The first bundle you build, and the first pin you are held to.

Skills: `nhcx-coverage`, whole. `nhcx-preauth` reuses the coverage builder for the auth-requirements purpose (7.6).

## Depends on

7.1, 7.2, 7.3.

## Inputs

- `nhcx-build/mapping.json` `bundles.coverage`
- `references/fhir-knowledge.md` section 3
- `references/transport-knowledge.md` sections 2 and 3.6 (the policy lookup, and why the processor is the recipient)
- `references/flow-knowledge.md` section 1 rows 1 and 2
- Pins: `nhcx-package/fhir/B1/discovery.json`, `B1/validation.json`, `B1/benefits.json`; answers under `nhcx-package/fhir/C3`

## Build

### Policy search

`transport.policies(id_type, value)`: the participant service's `participant/get/policies` with `identifiertype` and `identifiervalue`. Try `AbhaNumber` first, then `MemberId`, then `MobileNo`. Each policy carries `payerid`, `processingid`, `memberid`, `productid` and `productname`. Normalise it into `member_id` (`memberid`), `policy_code` (`productid`), `policy_name` (`productname`), `payer_code` (`payerid`: the insurer, named inside the bundle and the key of the payer adapter) and `recipient_code` (`processingid`: the envelope's recipient, whose certificate seals the message). A policy with no `processingid` cannot be addressed; say so rather than open a case on it. Create the episode (`claim` row) from the chosen policy, linking the HMIS patient. The published answer is a sketch: read a real one first and keep the raw JSON on the episode.

### The coverage request builder

A pure function `build_coverage_request(data) -> bundle` where `data` holds purpose, member id, policy code, payer code, facility (HFR id, name), the case number, `created`, and items (only on `benefits` and `auth-requirements`). Seven entries in the pinned order: CoverageEligibilityRequest, Patient, provider Organization, payer Organization, Location, Coverage, PractitionerRole. The Patient carries only the member id, typed `PMJAY` and `MB`. The Coverage identifier is `NH` = policy code, or `NONE` on discovery. Bundle id per purpose.

### The send

Workflow id = the case number. New correlation id per check. Store `txn_id`, `correlation_id`, `api_call_id` on the `claim` row's coverage columns; status `checking`.

### The reader

`parse_validation_bundle(bundle)`: the payer echoes the request and appends its own entries, so take the last `CoverageEligibilityResponse`, `Patient`, `Coverage`. Read `insurance[0].inforce`, `outcome`, `disposition`, `item[].authorizationRequired`, the largest `benefit[].allowedMoney` with its `usedMoney`, the Patient's name, gender, birth date, address, `ABHA` identifier and photo, the Coverage `class[0].name` and `period`. Status becomes `eligible` or `not-eligible`; the payer's demographics are stored on the episode (not written back to the HMIS patient unless stage 4 said so).

## Rules

- Validate, then discover, on a fresh episode (the sandbox's order); a `benefits` check is optional.
- The workflow id on these legs is the case number, not a code.
- Demographics on the request are the payer's to return. Send only the identifiers.

## Validate

- [ ] For each of `discovery`, `validation`, `benefits`: the builder fed the pin's data produces the pin, byte for byte in canonical JSON with `created` excluded.
- [ ] Every `reference` in the bundle resolves to a `fullUrl` in the same bundle.
- [ ] `Coverage.identifier` is `NONE` on discovery and the policy code otherwise.
- [ ] The Patient has exactly the two identifiers and no name.
- [ ] The reader fed each `nhcx-package/fhir/C3/*.json` yields `inforce`, `outcome`, and a non-empty patient name.
- [ ] A check sets `claim.status` to `checking` and stores the three exchange ids; the reader sets `eligible` or `not-eligible`.

## Tests

- One pin comparison per purpose (the skeleton in `references/testing-knowledge.md` section 4).
- One reader test per pinned payer answer.
- B1 from the matrix: validate then discover, two sends, two correlation ids, `eligible` at the end.

## Pseudo code

Builders and readers: `fhir/FHIR.md` section 2. Orchestration:

```
function search_policies(id_type, value):                        # AbhaNumber first, then MemberId, then MobileNo
    raw = transport.policies(id_type, value)                     # the participant service's participant/get/policies
    return [normalise_policy(p) for p in raw.policies or []]     # read a real answer first; keep raw on the episode

function normalise_policy(p):                                    # field names as NHA's sketch gives them; confirm on a real answer
    if not p.processingid: raise "this policy names no processor; it cannot be addressed"
    return {"member_id": p.memberid, "policy_code": p.productid, "policy_name": p.productname,
            "payer_code": with_hcx(p.payerid),                   # the insurer: inside the bundle, and the payer adapter's key
            "recipient_code": with_hcx(p.processingid),          # the processor: the envelope's recipient
            "raw": p}

function create_claim(policy, patient_id, encounter_id = null):
    row = insert("claim", {claim_no: next_claim_no(), member_id: policy.member_id, policy_code: policy.policy_code,
                           payer_code: policy.payer_code, recipient_code: policy.recipient_code, policy_json: policy.raw, patient_id, encounter_id, status: "draft"})
    stamp_case(row.id); return row

function run_check(claim_id, purpose):                           # validation, then discovery; benefits optional
    row = claim(claim_id); adapter = payers.for_claim(row)
    bundle = fhir.build_coverage_request({purpose, member_id: row.member_id, policy_code: row.policy_code if purpose != "discovery" else null,
                                          facility: settings.facility, payer: {participant_code: row.payer_code, name: payer_name(row)},
                                          created: now_ist(), items: []})
    row.status = "checking"; row.purpose = purpose; row.request_json = bundle; save(row)
    r = transport.send("v1/coverageeligibility/check", bundle, recipient_of(row), workflow_id = row.claim_no, claim_no = row.claim_no, usecase = "coverage-" + purpose)
    update(row, {txn_id: r.txn_id, correlation_id: r.correlation_id, api_call_id: r.api_call_id, sent_at: now()})
    stamp_case(claim_id)

APPLY["claim"] = function (row, env):                           # the coverage answer
    p = fhir.parse_validation_bundle(env.fhir)
    update(row, {status: "eligible" if p.inforce else "not-eligible", inforce: p.inforce, disposition: p.disposition,
                 allowed_amount: p.allowed, used_amount: p.used, patient_json: p.patient, response_json: env.fhir,
                 thread_correlation_id: env.jwe_headers["x-hcx-correlation_id"], answered_at: now()})
```
