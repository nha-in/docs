# M1 ABHA identity

Milestone 1 (M1) of [ABDM](/docs/hiecm/v3/getting-started/glossary#abdm) is the identity milestone: create an [ABHA](/docs/hiecm/v3/getting-started/glossary#abha) for a person, log that person in, and read or update their profile. An ABHA number is a 14 digit identifier issued after a strong [KYC](/docs/hiecm/v3/getting-started/glossary#kyc) check, and every other ABDM flow assumes the person already has one.

## What M1 gives you

| Capability | What your system can do |
|---|---|
| Session and tokens | Get an access token, refresh it, fetch NHA's public certificate |
| ABHA creation | Verify the person against Aadhaar, attach a mobile number and an ABHA address |
| ABHA login | Sign in a holder by mobile number, Aadhaar number, ABHA number or ABHA address |
| Profile management | Read the profile, show the ABHA card and quick response (QR) code, change the mobile number, redo KYC |

M1 does not move health records. [M2](/docs/hiecm/v3/api/m2) links them; [M3](/docs/hiecm/v3/api/m3) fetches them with consent.

## Building blocks used

- [ABHA registry](/docs/hiecm/v3/registries). Holds the ABHA number, address and profile.
- [HIE-CM](/docs/hiecm/v3/getting-started/glossary#hie-cm) gateway. Issues your session token. See [The ABDM gateway](/docs/hiecm/v3/concepts/gateway).

Aadhaar is not an ABDM building block. NHA's ABHA service calls it for you.

## Before you start

1. **Sandbox credentials.** A client ID and secret from [Get started](/docs/hiecm/v3/getting-started/sandbox).
2. **An access token.** From the session API, carried on every M1 call.
3. **NHA's public certificate.** The Aadhaar number, the [OTP](/docs/hiecm/v3/getting-started/glossary#otp) and the mobile number travel encrypted. NHA points at the RSA tool at [devbeaver.com](https://devbeaver.com/rsa-encryption-decryption-tool) for checking your encryption by hand.

## Base URLs

| Environment | Base URL |
|---|---|
| Sandbox | `https://abhasbx.abdm.gov.in/abha/api/v3/` |
| Production | `https://abha.abdm.gov.in/api/abha/v3/` |

Login by Aadhaar number using fingerprint or iris is the exception: NHA puts it on v3.1, at `https://abhasbx.abdm.gov.in/abha/api/v3.1/` in sandbox. NHA gives no production v3.1 URL.

## Build in this order

1. **Session and tokens.** Mandatory for both. Nothing else in M1 runs until this works.
2. **ABHA creation by Aadhaar OTP.** Mandatory for both.
3. **ABHA login.** Mandatory for both, on all four entry points.
4. **User profile and ABHA card.** Mandatory for both. Plain reads against a token you hold.
5. **Demographic authentication.** Mandatory for government integrators. Not required for private ones.

NHA marks everything else optional for both. Skip all of it and you still complete M1. The full mandatory and optional split, capability by capability, is on the [use cases](/docs/hiecm/v3/api/m1/sequence) page.
