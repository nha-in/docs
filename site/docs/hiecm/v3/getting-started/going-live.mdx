# Go live

Certified is not the same as live. Between the two sits an exit process you run once, at the
end.

## Before you start

You need a security audit by a CERT-In empanelled auditor, which produces the Safe to Host
certificate required before production. It is separate from any functional testing.

## 1. Certify each milestone your role needs

You certify one milestone at a time.
[Your integration path](/docs/hiecm/v3/milestones) says which ones apply to a
[PHR](/docs/hiecm/v3/getting-started/glossary#phr) application, a
[HIP](/docs/hiecm/v3/getting-started/glossary#hip) or an
[HIU](/docs/hiecm/v3/getting-started/glossary#hiu).

How to submit a milestone for certification is not documented here yet.

## 2. Complete the exit process

Run it after your integration is complete, not milestone by milestone. There are four steps, in
this order:

1. **Demonstration.** You demonstrate the
   [ABDM](/docs/hiecm/v3/getting-started/glossary#abdm) functionality you built to the ABDM
   integration team.
2. **Functional testing and security audit.** Empanelled agencies run these after the
   demonstration.
3. **Exit form submission.** You upload the exit form on the sandbox with the functional testing
   report and certificate, the security audit report, a signed undertaking, and any other
   supporting document we ask for.
4. **A second demonstration.** Once the earlier steps are complete, we schedule a demo for the
   Health Tech Committee. Different audience, different demonstration.

What the functional testing report and the undertaking have to contain is not documented beyond
their names. Confirm the evidence format with us rather than assuming it.

## 3. Switch to the production base URLs

Production credentials are issued after the exit process completes. They are not your sandbox
values.

| What you call | Sandbox | Production |
| --- | --- | --- |
| The gateway | `https://dev.abdm.gov.in`, `X-CM-ID: sbx` | `https://apis.abdm.gov.in`, `X-CM-ID: abdm` |
| The [ABHA](/docs/hiecm/v3/getting-started/glossary#abha) service | `https://abhasbx.abdm.gov.in/abha/api/v3/` | `https://abha.abdm.gov.in/api/abha/v3/` |

A production client id against a sandbox host, or the reverse, fails.

## What you see when it works

You hold a production client id and client secret, and a call that worked in the sandbox returns
the same result against the production host.

If it does not, check the base URL and the `X-CM-ID` header first. See
[Everything returns 401](/docs/hiecm/v3/troubleshooting/everything-returns-401).
