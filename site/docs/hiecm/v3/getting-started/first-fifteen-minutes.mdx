# Make your first call

Your first [ABDM](/docs/hiecm/v3/getting-started/glossary#abdm) call creates a session. It
returns the token every other call carries.

## Before you start

Have your `clientId` and `clientSecret` in hand. If you do not,
[get your sandbox credentials](/docs/hiecm/v3/getting-started/sandbox) first.

## 1. Create a session

Send this, with your two credentials filled in and a fresh `REQUEST-ID` and `TIMESTAMP`.

```bash
curl --request POST \
  --url https://dev.abdm.gov.in/api/hiecm/gateway/v3/sessions \
  --header 'REQUEST-ID: 5f7a4a1e-59ba-4c0c-9e0c-8e6b3b6e2f11' \
  --header 'TIMESTAMP: 2026-08-25T15:51:15.339Z' \
  --header 'X-CM-ID: sbx' \
  --header 'Content-Type: application/json' \
  --data '{
  "clientId": "<CLIENT_ID_FROM_SANDBOX_REGISTRATION>",
  "clientSecret": "<CLIENT_SECRET_FROM_SANDBOX_REGISTRATION>",
  "grantType": "client_credentials"
}'
```

| Header | What to send |
| --- | --- |
| `REQUEST-ID` | A fresh UUID per request. Do not reuse one. |
| `TIMESTAMP` | The current time in ISO 8601, in UTC. |
| `X-CM-ID` | `sbx` on the sandbox, `abdm` in production. |

*Example values shown; run it to see your own.*

## 2. Read the response

A session call answers `200` and returns five fields: `accessToken`, `expiresIn`,
`refreshExpiresIn`, `refreshToken` and `tokenType`. The
[gateway session reference](/reference/hiecm-gateway) says what each one means.

`accessToken` is the one you need next. `expiresIn` tells you when to ask for another.

## 3. Use the token on every call

Send the token as a header on every later call:

```
Authorization: Bearer <ACCESS_TOKEN_FROM_SESSIONS_CALL>
```

Keep sending a fresh `REQUEST-ID`, a current `TIMESTAMP` and `X-CM-ID: sbx` alongside it.

## What you see when it works

A `200`, a body carrying `accessToken`, and a later call that no longer returns 401.

If it fails, see [Everything returns 401](/docs/hiecm/v3/troubleshooting/everything-returns-401).
