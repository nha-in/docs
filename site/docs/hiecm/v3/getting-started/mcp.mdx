# Docs MCP server

An MCP server that serves this catalogue to your coding agent. The agent searches it while it works and retrieves the paragraph it needs, rather than holding the whole site in its context.

<McpInstall />

Pick your editor above and the install is one click; any other MCP client takes the server address from those commands, over streamable HTTP. The [agent skills](/docs/hiecm/v3/getting-started/build-with-ai) carry the same facts as files an agent loads once; the server is those facts served live, at the current catalogue version.

## Which one you want

Both carry the same content, generated from the same catalogue. They differ in how the agent gets it.

| | Agent skill | MCP server |
|---|---|---|
| How the agent gets it | One markdown file, loaded whole | Queried on demand, a few results at a time |
| Freshness | The copy you downloaded | Whatever the catalogue holds now |
| Scope | One module | Every gateway and module here |
| Context cost | The whole file, every session | Only what it retrieved |
| Works offline | Yes | No |

A skill is the better fit when you are working through one module and want the rules always in front of the agent. The server is the better fit for a question you did not plan for, and for checking a request or an error code against what the catalogue says right now.

## What it will not do

It answers from this catalogue and nothing else. It does not call ABDM, hold your credentials, or reach the sandbox, so it cannot tell you what an endpoint really returns. Every answer carries the same `unverified` marking the pages do.

## Guided FHIR skills

Two skills turn this server's FHIR tools into a procedure your agent follows end to end: building NRCES compliant document bundle generation into your own codebase, or auditing what your existing FHIR store produces. Both live on [Build with AI](/docs/hiecm/v3/getting-started/build-with-ai) with the rest of the agent tooling; unlike the module skills, they need this server connected, because every step calls its tools.
