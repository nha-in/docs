# Module 7.2: storage

Purpose: the tables from `mapping.json`, created the way the target creates tables.

Skills: the foundation (`core/FOUNDATION.md`). The first skill that needs storage creates the episode table; every skill adds the leg tables its `SKILL.md` lists, in its own migration.

## Depends on

7.1 (only for the settings mechanism; no code dependency).

## Inputs

- `nhcx-build/mapping.json` `tables` and `legs`
- `nhcx-build/3-discovery.md` (migration tool, naming conventions)

## Build

One migration (or schema block) per table in `mapping.json` whose home is `sidecar` or `add_columns`. Under the target's naming convention. The columns are the ones `mapping.json` lists; the types follow the target's engine.

Non-negotiable columns:

| Where | Columns | Why |
| --- | --- | --- |
| Every leg table (`claim_preauth`, `claim_submission`, `claim_enquiry`, `claim_predetermination`, `claim_query`, `claim_payment`, `claim_auth`, `claim_plan`, and the coverage columns on `claim`) | `txn_id`, `correlation_id`, `api_call_id`, `thread_correlation_id`, `status`, `request_json`, `response_json`, `error_message`, `sent_at`, `answered_at` | The thread, the dedupe key, the audit trail, the door-refusal recovery |
| `claim_preauth`, `claim_submission` | `submission_kind`, `workflow_id`, `preauth_ref`, `eligible_amount`, `submitted_amount`, `items_json`, `query_note` | What was sent, what the payer said, the in-band query text (PMJAY) |
| `claim` | `claim_no` unique, `member_id`, `policy_code`, `payer_code`, `recipient_code`, `patient_id`, `encounter_id`, `stage`, `sub_stage`, `plan_id` | The episode |
| `claim_query` | `correlation_id` unique, `request_id`, `kind` (query, notification, note), `reason_code`, `status` (open, answered, acknowledged, error), `questions_json`, `reply_text`, `reply_document_ids` | The inbox |
| `claim_payment` | `correlation_id` unique, `amount`, `utr`, `payment_status`, `ack_status`, `ack_txn_id` | Payment, deduped on the payer's thread |
| `claim_document` | `code`, `category`, `stage`, `content_type`, bytes or a pointer, `title` | Attachments with the payer's own code |
| `claim_plan_benefit` | `code`, `display`, `category`, `rate`, `kind`, `conditions_json`, `extras_json`, `supporting_info_json` | The flattened master |
| `claim_plan_form` | `url` unique per plan, `title`, `kind` (policy, stg), `questions_json` | The questionnaires |

Foreign keys to the HMIS's patient, encounter and practitioner tables use the HMIS's own key types. Cascade deletes from `claim` to its children.

A `claim_plan` row may run to tens of megabytes of `response_json` (a PMJAY master). Choose a column type that holds it, or store the raw bundle in the archive and keep only the flattened rows.

## Rules

- Sidecar tables by default. Add a column to an HMIS table only where `mapping.json` says `add_columns`, and only for the scalar it names.
- One `correlation_id` per leg row, never one on the episode for all legs. `claim.correlation_id` holds the coverage check's thread only.
- The uniqueness of `claim_query.correlation_id` and `claim_payment.correlation_id` is what dedupes a redelivered inbound request. Make it a constraint, not a check in code.
- The claim number (`next_claim_no`) is any short, unique, sortable number per hospital that fits the payer's `CLN` identifier.

## Validate

- [ ] Every table in `mapping.json` with home `sidecar` exists after migration; every `add_columns` entry's columns exist on the named HMIS table.
- [ ] Every leg table has `txn_id`, `correlation_id`, `api_call_id`, `thread_correlation_id`.
- [ ] `claim.stage` and `claim.sub_stage` exist.
- [ ] `claim_query.correlation_id` and `claim_payment.correlation_id` are unique.
- [ ] The migration runs twice without error (idempotent or guarded).
- [ ] Deleting a `claim` row removes its children.

## Tests

- Migrate a fresh database; assert the table and column list against `mapping.json` programmatically.
- Insert two `claim_query` rows with one correlation id; assert the second fails.
- Delete a claim with children; assert the children are gone.

## Pseudo code

```
# One migration per table; SQL shown, translate to the ORM. Every leg table shares the exchange columns.
EXCHANGE_COLUMNS = """
    txn_id TEXT, correlation_id TEXT, api_call_id TEXT, thread_correlation_id TEXT,
    status TEXT NOT NULL DEFAULT 'draft', request_json TEXT, response_json TEXT, error_message TEXT,
    sent_at TEXT, answered_at TEXT"""

CREATE TABLE claim (
    id INTEGER PRIMARY KEY, claim_no TEXT UNIQUE NOT NULL,
    member_id TEXT, policy_code TEXT, payer_code TEXT, recipient_code TEXT, policy_json TEXT,   -- payer_code: the insurer (payerid); recipient_code: the processor (processingid), the envelope's recipient
   
    patient_id <HMIS key type> REFERENCES <hmis patient>(id), encounter_id <key> REFERENCES <hmis encounter>(id),
    plan_id INTEGER REFERENCES claim_plan(id),
    purpose TEXT, inforce INTEGER, allowed_amount REAL, used_amount REAL, disposition TEXT,   -- the coverage leg lives here
    stage TEXT, sub_stage TEXT, created_at TEXT, {EXCHANGE_COLUMNS});

CREATE TABLE claim_preauth (
    id INTEGER PRIMARY KEY, claim_id INTEGER NOT NULL REFERENCES claim(id) ON DELETE CASCADE,
    submission_kind TEXT, workflow_id TEXT, preauth_ref TEXT, claim_ref TEXT,
    eligible_amount REAL, submitted_amount REAL, approved_amount REAL, items_json TEXT, query_note TEXT,
    cancel_txn_id TEXT, cancel_correlation_id TEXT, cancel_status TEXT, cancel_error TEXT, {EXCHANGE_COLUMNS});

CREATE TABLE claim_submission (... as claim_preauth, plus discharge_mode TEXT, discharge_stage TEXT,
    discharged_at TEXT, surgery_at TEXT, death_at TEXT ...);

CREATE TABLE claim_query (
    id INTEGER PRIMARY KEY, claim_id INTEGER REFERENCES claim(id) ON DELETE CASCADE,
    correlation_id TEXT UNIQUE NOT NULL, request_id TEXT, workflow_id TEXT, sender_code TEXT,
    kind TEXT NOT NULL,            -- query | notification | note
    stage TEXT, reason_code TEXT, intent TEXT, questions_json TEXT, request_json TEXT,
    status TEXT NOT NULL DEFAULT 'open',   -- open | answered | acknowledged | error
    reply_text TEXT, reply_document_ids TEXT, reply_txn_id TEXT, reply_api_call_id TEXT, replied_at TEXT, received_at TEXT);

CREATE TABLE claim_payment (
    id INTEGER PRIMARY KEY, claim_id INTEGER REFERENCES claim(id) ON DELETE CASCADE,
    correlation_id TEXT UNIQUE NOT NULL, workflow_id TEXT, sender_code TEXT,
    amount REAL, payment_status TEXT, payment_date TEXT, utr TEXT, notice_json TEXT,
    ack_status TEXT DEFAULT 'pending', ack_txn_id TEXT, ack_api_call_id TEXT, acked_at TEXT, received_at TEXT);

CREATE TABLE claim_payment_detail (id, payment_id REFERENCES claim_payment(id) ON DELETE CASCADE, type TEXT, amount REAL);
CREATE TABLE claim_plan (id, policy_code, provider_id, payer_code, name, fetched_at, benefit_count, form_count, {EXCHANGE_COLUMNS});
CREATE TABLE claim_plan_benefit (id, plan_id REFERENCES claim_plan(id) ON DELETE CASCADE, code, display, category_code, category_display,
    rate REAL, kind TEXT, conditions_json, extras_json, supporting_info_json, UNIQUE(plan_id, code));
CREATE TABLE claim_plan_form (id, plan_id ..., url TEXT, title, kind TEXT, questions_json, UNIQUE(plan_id, url));
CREATE TABLE claim_auth (id, claim_id ..., fingerprint TEXT, {EXCHANGE_COLUMNS});
CREATE TABLE claim_auth_item (id, auth_id ..., code, authorised INTEGER, excluded INTEGER, benefit_json);
CREATE TABLE claim_auth_requirement (id, auth_id ..., line_code, kind TEXT, code, display, url, stage TEXT, at_preauth INTEGER);
CREATE TABLE claim_line (id, claim_id ..., kind TEXT, code, display, category_code, category_display, quantity INTEGER, unit_price REAL, amount REAL, parent_code TEXT, UNIQUE(claim_id, kind, code));
CREATE TABLE claim_form_answer (id, claim_id ..., form_url, link_id, answer TEXT, document_id, stage TEXT, UNIQUE(claim_id, form_url, link_id, stage));
CREATE TABLE claim_document (id, claim_id ..., code, category, stage TEXT, content_type, title, bytes BLOB or storage_key TEXT, size INTEGER, uploaded_at);
CREATE TABLE claim_enquiry (id, claim_id ..., kind TEXT, stage TEXT, reason_code, amount REAL, document_ids, answer TEXT, {EXCHANGE_COLUMNS});
CREATE TABLE claim_predetermination (id, claim_id ..., items_json, eligible_amount, {EXCHANGE_COLUMNS});
CREATE TABLE claim_diagnosis (id, claim_id ..., code, display);
CREATE TABLE claim_care_team (id, claim_id ..., practitioner_id <HMIS key>, role TEXT, sequence INTEGER);
CREATE TABLE claim_item (id, claim_id ..., code, display, quantity, unit_price, amount);

function next_claim_no():                       # any short, unique, sortable number per hospital that fits the payer's CLN identifier
    return hospital_prefix() + sortable_serial()   # the format is yours
```
