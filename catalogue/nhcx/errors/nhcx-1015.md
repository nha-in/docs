# NHCX-1015: the client is not allowed to change this participant's registry details

## In plain words

The participant registry refused a change to a participant's record because the client id behind your token is not the one that created the participant. Only the creator's credentials can change the endpoint URL or the encryption certificate through the API. Anyone else changes them on the NHCX portal or through NHCX support.

The message text on the live registry is:

```text
You are not authorized to update/modify details
```

The Standard Error Codes sheet prints `Invalid response received from receiver.` for this code, the same text it prints for [NHCX-1017](nhcx-1017.md). Read an invalid receipt as NHCX-1017. Read NHCX-1015 as this registry refusal.

## Before you start

You called the participant registry to change a record: [`/participant/update`](../endpoints/participant-update.md), [`/v2/participant/update`](../endpoints/v2-participant-update.md) or [`/v2/update/cert`](../endpoints/v2-update-cert.md). The call carried a bearer token minted from a client id and secret.

The registry answers this code on the same connection, in the body of the call, with the code in `error.code` and the text in `error.message`. It is not sealed, and it does not arrive on `/v1/error`.

## What happens

The registry looks up which client id created the participant named in the body. When the token's client id is a different one, it refuses the change and answers with NHCX-1015. Nothing in the record changes.

This happens when:

- One person registered the participant under one set of credentials and another person updates it under a different set.
- The participant was created on the NHCX portal or by NHCX support, and the API update carries credentials the registry does not tie to it.
- The token was minted for a different participant than the one named in `participant_code`.

## How you know it worked

Send the same update with the creator's credentials. You receive HTTP 200 with your own `participant_code` in the body, and `error.code` is empty.

[`/participant/search`](../endpoints/participant-search.md) with your code returns the new `endpoint_url` or `encryption_cert`.

## When it goes wrong

1. Find the client id that created the participant. The team that onboarded it holds those credentials.
2. Mint a token with those credentials and send the update again.
3. If the creator's credentials are gone, change the record on the NHCX portal, or ask [NHCX support](../sandbox/support-contacts.md) to change it. Give support the `participant_code` and the message text.

Retrying with the same credentials does not change the answer. A `401` instead of this code is a token fault, not a permission fault. See [NHCX-401](nhcx-401.md).
