# PAYR-1008: the beneficiary's remaining cover is not enough for the request, or the FHIR bundle is not valid or cannot be parsed

## In plain words

PAYR-1008 has two meanings, depending on which payer sent it, and the PMJAY payer also uses it for fifteen messages the error sheet prints without a code.

- From a payer using the standard payer codes: the beneficiary's remaining cover is not enough for the request.
- From the [PMJAY](../glossary/pmjay.md) payer: the [FHIR](../../shared/glossary/fhir.md) bundle is not valid or cannot be parsed.
- From the PMJAY payer, with one of the fifteen texts listed below: an attachment, an identifier or a Task input the payer refuses. The Bridge Error sheet prints these rows with an empty code cell. On the wire they arrive as PAYR-1008.

Read the code together with the message text that comes with it. The text tells the meanings apart.

## Before you start

You sent a request through [NHCX](../../shared/glossary/nhcx.md), and the payer answered it with an error. The answer arrives on the `on_` path paired with your request, such as `/v1/preauth/on_submit` or `/v1/claim/on_submit`. `x-hcx-status` marks it as an error. `x-hcx-error_details` carries the code in `code` and the text in `message`.

Read these fields from the protected header once you open the [JWE](../glossary/jwe.md). Some payers send the same fields in a plain `ProtocolResponse` body instead. Handle both.

A payer using the standard payer codes sends PAYR-1008 for preauthorisation and claim.

## What happens

| Message text | Sent by | Meaning |
|---|---|---|
| `Eligible coverage amount of the beneficiary for the requested policy is insufficient to process the request.` | A payer using the standard payer codes | The beneficiary's remaining cover is not enough for the request. |
| `Invalid FHIR bundle received. Hence request will not be processed further.` | The PMJAY payer | The FHIR bundle is not valid or cannot be parsed. |

### When the standard meaning applies

- The amount requested is more than the beneficiary's remaining cover under the policy.

### When the PMJAY meaning applies

- The bundle is not valid, or the payer cannot parse it.

### The fifteen texts the sheet prints without a code

The Bridge Error sheet lists these fifteen messages directly under PAYR-1008 with an empty code cell. The PMJAY payer sends each of them as PAYR-1008. The `message` field is the only way to tell them apart.

| Message text | Meaning |
|---|---|
| `Invalid input, code and reason code received. Please try again with valid combination. To get the valid combination for task request, please refer to the document.` | A Task carries a code and reason code pair the scheme does not accept. |
| `Invalid case number received. Please try again with valid case number.` | The case number on a Task or claim is not one the payer holds. |
| `Invalid Base64 value received in attachment. Please try again with valid Base64 value. Please refer to https://hl7.org/fhir/R4/datatypes.html#Attachment` | An attachment's `data` is not valid Base64. |
| `Invalid attachment name received in attachment. Please try again with valid name.` | An attachment has no `title`, or one the payer refuses. |
| `Invalid content type received in attachment. Please try again with valid name. Applicable content types are - application/pdf, application/jpg, application/jpeg, application/png, application/fhir+json. For further information please refer to NHCX Integration Handbook document.` | An attachment's `contentType` is outside the five the payer reads. |
| `No user role found/associated for sender code %s in NHCX system. Please try again with valid sender details.` | The sender has no role in the NHCX registry. |
| `Invalid HFR Id received. Please try again with valid HFR details.` | The HFR id in the bundle is not one the payer knows. |

Please ensure the HFR id sent in the FHIR request must match with the registry id specified in NHCX for the sender.` | The HFR id in the bundle is not the registry id NHCX holds for the sender. |

| `Invalid Base64 value received in attachment for date of birth for new born beneficiary. Please try again with valid Base64 value. Please refer to https://hl7.org/fhir/R4/datatypes.html#Attachment` | The newborn date of birth attachment's `data` is not valid Base64. |

## How you know it worked

Send the corrected request. The step is done when the payer answers without this code:

- For a preauthorisation, `/v1/preauth/on_submit` arrives with no `x-hcx-error_details`. Its `x-hcx-workflow_id` names the decision, for example `21` approved or `24` queried.
- For a claim, `/v1/claim/on_submit` arrives with no `x-hcx-error_details`, and its bundle carries a `ClaimResponse`.

## When it goes wrong

### If the text reads `Eligible coverage amount of the beneficiary for the requested policy is insufficient to process the request`

1. Check the remaining cover with a coverage eligibility check. See [Check coverage eligibility](../flows/coverage-eligibility-check.md).
2. Request no more than the remaining cover.
3. Send the request again with a fresh `x-hcx-correlation_id`. Reusing the old one returns [NHCX-1006](nhcx-1006.md).

### If the text is one of the fifteen without a code

1. Match the text against the table above and fix the element it names: the attachment's `data`, `title` or `contentType`, the HFR id, the hospital id, the case number, or the Task's code and reason code pair.
2. For an attachment, send `application/pdf`, `application/jpg`, `application/jpeg`, `application/png` or `application/fhir+json`, with valid Base64 in `data` and a name in `title`.
3. For an HFR id fault, send the registry id NHCX holds for the sender. For a role fault, confirm the sender's registration with [NHCX support](../sandbox/support-contacts.md).
4. Send the request again with a fresh `x-hcx-correlation_id`. Reusing the old one returns [NHCX-1006](nhcx-1006.md).

### If the text reads `Invalid FHIR bundle received`

1. Validate the bundle with the [NRCeS](../../shared/glossary/nrces.md) validator. See [the validator recipe](../../shared/fhir/hl7-validator-recipe.md) and [validating an NHCX bundle](../fhir/validation.md).
2. Fix every error the validator reports.
3. Send the request again with a fresh `x-hcx-correlation_id`. Reusing the old one returns [NHCX-1006](nhcx-1006.md).
4. If it still fails, contact NHCX support. See [support contacts](../sandbox/support-contacts.md).
