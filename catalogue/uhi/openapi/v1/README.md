# UHI V1 specifications

Three OpenAPI 3.1 files, generated by `scripts/ingest-uhi.mjs` from NHA's UHI
set of 28 September 2026 (`catalogue/uhi/openapi/.raw/nha-2026-09-28-uhi/`). Never
edit them by hand: change the script, rerun it, and the correction log at
`catalogue/uhi/openapi/corrections/2026-09-28-uhi-ingest.md` records the edit.

| File | Module | What it holds |
| --- | --- | --- |
| `uhi-network.yaml` | `network` | The Gateway search and on_search, the discovery pair every HSPA and EUA serves, and the network registry lookup. Examples for all six services |
| `uhi-consultation.yaml` | `consultation` | Physical Consultation from select to on_message, and the four Gateway audit endpoints |
| `uhi-ambulance.yaml` | `ambulance` | Ambulance Booking's init and on_init |

PM-JAY HEM, Blood Bank, Jan Aushadhi and NOTTO are discovery only, so they
have no file of their own: their flows are journeys over the network
operations, in `journeys/network.yaml`.

Participant calls are `paths`, not `webhooks`, with `x-abdm-hosted-by` saying
who serves each one. See `../../CONVENTIONS.md`, "UHI is the exception".

Two rules the build enforces:

- The file name must be unique across the whole `openapi/` tree, because it is
  the served path and the Scalar route.
- Generated pages carry `generated: true`. Never hand-write a page at a
  generated name; the build stops rather than overwrite one.
