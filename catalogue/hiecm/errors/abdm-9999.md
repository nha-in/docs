# ABDM-9999, a catch-all, so read the message

## In plain words

`ABDM-9999` covers many failures, and the message carries the meaning. Some messages report a problem in your request, for example "Invalid Transaction Id", "Invalid LoginId" or "RequestId cannot be NULL or Blank". Others mean ABDM or the [HIP](/docs/hiecm/v3/getting-started/glossary#hip) could not process it, for example "Unknown exception" or "Cannot process the request at the moment, please try later."

## What happens

The code may arrive bare or followed by a colon and a space. Match on the code, then branch on the message. More specific codes exist for an unavailable service: `ABDM-1019` and `ABDM-1024` for a dependent service, `ABDM-1028` for the HIP and `ABDM-1033` for the HIU.

## How you know it worked

After a request problem, the corrected request succeeds. After an unavailability message, the same request succeeds later, unchanged.

## When it goes wrong

For a request problem, fix the field the message names, because a retry repeats the mistake. For an unavailability message, retry with exponential backoff and a cap on attempts, so the loop does not end in [ABDM-1022](#abdm-1022). If it persists for hours, report it through [Support](/docs/support) with your `REQUEST-ID` and `TIMESTAMP`.
