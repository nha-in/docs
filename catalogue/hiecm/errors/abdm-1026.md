# ABDM-1026, the token that authorises care context linking is not usable

## In plain words

Linking a care context needs a link token, and the one you sent is not
valid for this link.

NHA lists several closely related codes here, which is a sign that link
tokens are where M2 integrations get stuck.

## Before you start

You have received this code in a response body. Nothing else is assumed.

## What happens

NHA's own wording for this code is "Invalid Link Token".


  The token has expired, was issued for a different ABHA address, or was
  issued for a different HIP.

  NHA has separate codes for the mismatches: `ABDM-1038` for an address
  mismatch, `ABDM-1062` for a number mismatch and `ABDM-1063` for a HIP
  mismatch. Getting this generic code instead usually means expiry or
  malformation.

## How you know it worked

The link call is accepted and the confirming callback arrives naming the care contexts you sent.

## When it goes wrong

Validate the token before use rather than after failure. It is a JWT, so
its expiry is readable without calling anything.

If it has expired, regenerate it through demographic authentication. Do
not retry the same token.
