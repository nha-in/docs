## In plain words

ABDM-1113 is HTTP 400 with the message
`Duplicate health information provider data flow response`. Your
acknowledgement of a health information request carried a
`transactionId` the gateway had already been acknowledged for. The
sandbox remembers a transaction id across runs, so an acknowledgement
built from a sample body is refused on its first send.

## Before you start

Know where the `transactionId` in your body came from. It arrives on
[the health information request](hiecm.callback.m2-on-health-information-request);
you never choose it.

## What happens

Conditions that produce this error: acknowledging the same request
twice, which happens when the gateway redelivers the request and your
handler is not idempotent, or sending an id copied from documentation
or from an earlier transfer.

## How you know it worked

The acknowledgement returns 200 and the data flow continues to the push
and the notify.

## When it goes wrong

Acknowledge once per `transactionId`. Dedupe inbound requests on their
`REQUEST-ID` header so a redelivery does not produce a second
acknowledgement. On a timeout, treat a following ABDM-1113 as proof the
first one landed and move on to the push.
