# ABDM-2404, the REQUEST-ID is not valid

## In plain words

The `REQUEST-ID` header is missing or is not a universally unique identifier (UUID). The message is "Invalid Request Id". In the asynchronous flows this value is how a callback is matched to your call, so a bad one breaks that match too. A request id that was already used returns [ABDM-1064](/docs/hiecm/v3/api/m2/errors#abdm-1064) instead.

## How you know it worked

The call returns its normal response, and in an asynchronous flow the callback's `requestId` matches the `REQUEST-ID` you sent.

## When it goes wrong

Generate a fresh UUID for every request and log it before sending. A retry is a new request and takes a new value.
