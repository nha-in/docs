## In plain words

In the data flow, ABDM-1101 is HTTP 400 with the message
`Duplicate Health Information request`. The `transactionId` in your
notify or your request has been used before. The gateway keeps
transaction ids across sessions, so a body copied from an example, or
from a previous run, is refused even on a fresh day. The sandbox
remembers a transaction id across runs: the recorded refusals came from
resending the specification's own example id.

In M1 the same code means the ABHA address you tried to claim already
exists.

## Before you start

Know where the `transactionId` in your body came from. It is issued by
the gateway on the on-request callback for that data flow, never chosen
by you.

## What happens

Conditions that produce this error: sending the data flow notify twice
for one transaction, sending it with a transaction id from an earlier
transfer or from a sample body, or raising a second health information
request that repeats an id.

## How you know it worked

The notify returns 202 with `{"status":"Notification is Accepted"}`.
For the M1 case, the address claim returns 200.

## When it goes wrong

Send the notify once per transaction, with the `transactionId` the
gateway gave you on the on-request callback. On a timeout, treat a
following ABDM-1101 as proof the first one landed. Never reuse an id
from documentation or a previous run. For the M1 case, ask the address
suggestion call for another address.
