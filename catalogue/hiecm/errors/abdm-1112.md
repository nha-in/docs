# ABDM-1112, the consent you are fetching against is no longer usable

## In plain words

The consent artefact you presented is unknown, expired or revoked.

This is often not a bug. A patient is allowed to revoke consent, and a
consent window is allowed to end.

## Before you start

You have received this code in a response body. Nothing else is assumed.

## What happens

NHA's own wording for this code is "Invalid or already expired consent artefact id".


  Three conditions: the identifier is wrong, the window has passed, or the
  patient revoked.

  ABDM does not distinguish between them here, which is deliberate: telling
  a requester that a specific consent was revoked is itself information
  about the patient.

## How you know it worked

A fetch against a currently granted artefact is accepted and the data callback arrives.

## When it goes wrong

Check the artefact's expiry before fetching, and treat revocation as a
normal state your system handles rather than an error it reports.

If you need continued access, raise a new consent request. Do not retry
against the old artefact.
