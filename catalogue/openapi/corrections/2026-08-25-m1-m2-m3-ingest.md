# Corrections, M1 to M3 ingest, 25 August 2026

NHA supplied three OpenAPI files and four Postman collections. The raw files
are stored untouched under `catalogue/openapi/.raw/` with their sha256
hashes, and every departure from them is listed here. Nothing was fixed
silently.

Source hashes are recorded in each module spec under `x-abdm-sources`.

## What the sources were worth

The specifications are better than most vendor OpenAPI. All 70 operations
carry an `operationId`, a `summary` and a `description`, which is what an
agent reads when choosing a tool. `ABDM_M1_API_Swagger.yaml` passes our
ruleset with no changes at all.

The one structural gap is large: **none of the three files describes a single
callback**. What NHA models as paths is the outbound half, including the
`on-discover`, `on-init` and `on-notify` responses that you send. What the
gateway posts to your registered URL is absent. For M2 and M3 that is half
the integration.

## C1: em dashes in NHA's prose

52 em dashes across the three files, in summaries and descriptions.

Rule P3 blocks U+2014 anywhere in the Catalogue. An em dash between spaces
became a comma; one without became a colon. Wording is otherwise NHA's.

Counts: M1 19, M2 12, M3 21, gateway 2.

## C2: references to components that do not exist

8 references resolved to nothing in NHA's own files, mostly on the session
and bridge group.

Where the target existed in a sibling milestone file it was copied in, which
is legitimate because NHA repeats that group across all three. Where it
existed nowhere, a placeholder object carries a description saying so. Those
placeholders are marked and should be replaced once NHA publishes the schema.

## C3: format assertions the examples contradict

26 `format: uuid` assertions removed, on `consentId`, `consentRequestId` and
`id`.

NHA's own examples for these fields are not UUIDs. Either the format is wrong
or the examples are, and we cannot tell which from the documents. Rather than
assert either, the constraint is dropped and the field stays a string. Each
site carries `x-abdm-correction: C3`.

**This one needs settling against the sandbox.** If real identifiers are
UUIDs, the assertion should come back.

## C4: hiType given as a string where the schema says array

2 sites, both in M2 user initiated linking.

`hiType` is a list of health information types and NHA's schema says so. The
examples give a bare string. The examples were corrected to arrays, which is
fixing something malformed rather than deciding what the contract should be.

## C5: an example that violates its own schema

1 site, the M3 consent fetch 200 response.

NHA's example omits `permission.frequency`, which NHA's schema makes
required. Supplying a value would be inventing one, so the example is
dropped and the response description says why. The original is in `.raw/`.

## Not a correction, a structural decision

The session, certificate and bridge group is repeated in all three milestone
files. It is described once in `hiecm-gateway.yaml` and removed from the
module files, so a change lands in one place. See
`catalogue/hiecm/decisions/spec-per-module.md`.

## Still missing after this ingest

- **M2's inbound callbacks.** The gateway to HIP discovery, link init, link
  confirm and consent notify payloads are in neither the specification nor
  the collection. They are declared as webhooks with a path and no body.
- **Verification.** Nothing here has been run against the sandbox from this
  repository. Every atom generated from it is `unverified`.
