Check the preconditions for `$ARGUMENTS` before building anything. With no argument, check what every module needs.

Each item below can fail in a way that reads as something else, which is why they are checked first rather than diagnosed later.

## Every module

- **The clock.** `TIMESTAMP` in UTC, ISO-8601 with milliseconds and a trailing `Z`, as in `2022-10-06T15:10:00.587Z`.
- **A fresh REQUEST-ID per call**, generated by you and logged before sending. Once a call has failed it is the only handle on it.
- **The gateway session token**, in `Authorization: Bearer`. A numeric code with a `description` field means this is wrong or expired.
- **`X-CM-ID`** set for the environment you are calling.

## M1, and every module that encrypts

- **The certificate**, fetched rather than pinned from a sample, with the padding read from its `encryptionAlgorithm`.
- **The padding proved, not assumed.** Run `/abdm-prove-encryption` first. A wrong padding can read as a wrong value.
- **The two tokens kept apart.** The gateway token goes in `Authorization`; the user token from an enrolment or login goes in `X-token`. Profile endpoints need both.

## M2 and M3

- **The role you are acting in**, HIP for M2 and HIU for M3.
- **A reachable callback URL**, on the public internet, that you can watch while you test. Most of M2 and M3 is answered asynchronously, so a flow that looks stuck is usually a callback you never received.
- **A link token per patient** for M2, validated before use rather than assumed live.

## M4

- **The M4 token**, from `POST /getManagementToken`.
- **The M4 certificate** from `/api/v1/auth/cert`. Do not reuse an M1 encryption path here.

## Output

One line per item: what was checked, and what was observed. Name anything you could not check rather than passing it silently.
