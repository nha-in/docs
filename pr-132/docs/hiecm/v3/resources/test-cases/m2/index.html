M2 test cases

The 36 cases M2 Health Information Provider is tested against. They cover creating health records, linking care contexts to an ABHA address whether your facility or the patient starts it, and sharing records when a consent arrives. Each row keeps the case id the functional testing report uses, and links every API the case calls. How to read a case explains the columns and markings.

An AI coding assistant can walk these cases against your own system with the M2 skill.

1. Health Record Creation​

Applies to: HIP.

The system should have a provision to create digital health records

7. Sending Notification for deep link workflow​

Applies to: HIP.

Case and markingWhat is testedPass whenAPIs
HIP_INIT_NOTIFY_HIECM
Mandatory		sending notification to the patient on their mobile with deep link
HIP should notify HIE-CM when a new health record is generated & ABHA address is not available.
This test case is applicable when patient has shared mobile number and has NOT shared ABHA address with HIP during patient registration.
Steps1. New health record like Diagnostic report, Prescription, etc is created on EMR/HMIS system for a patient
2. Mobile number of patient is available in EMR/HMIS system and ABHA address of the patient is NOT available in EMR/HMIS system
3. EMR/HMIS system will call the SMS/notify2 API on the gateway to inform of available of new health record (only the mobile number and the HIP ID is to be shared)
4. ABDM should be sending notification to the patient on their mobile with deep link
5. Patient should be able to download/launch PHR app of their choice
6. PHR app will make a discovery request to the HIP
7. Care context for New patient record must be correctly discoverable in the PHR app.
SMS sent with deep link-
1. Beneficary will share their mobile number, not an ABHA address or ABHA Number.
2. Beneficary will receive an SMS from ABDM.
3. User clicks on the link provided in the SMS, it will open in a browser, allowing them to install the PHR app.
4. After installation, the patient can continue with the Discovery flow to link their health record with the ABHA Address.
Kindly Note:
After being linked, the record must be visible in their HIMS along with the ABHA Address and ABHA Number.		POST /api/hiecm/hip/v3/link/patient/links/sms/notify2

8. Data transfer & share​

Applies to: HIP.

Case and markingWhat is testedPass whenAPIs
HIP_INIT_SHARE_CARECONTEXT
Mandatory		HIP must share health records associated with care context on request
Steps1. Initiate a "Get data" for a linked care context in the PHR app
2. HIP will receive a request to share information along with the consent id & end-point URL where the data must be pushed
3. HIP must verify that there is a valid consent for sharing this data with the specific HIU making the request
4. Health records must be shared only for allowed HIP types withing the date ranges granted in the consent
5. HIP should encrypt the health records to be shared with the HIU public key.
6. HIP should push the encrypted data to the end-point URL.
7. On successful transfer, HIP must notify HIE-CM of successful transfer by calling health information notify API.
8. Transfer must be completed within 2 hours of receiving the request.
1. Health records will be successfully received in the PHR app
2. Health records must be properly decryptable using the HIP public key
3. Health records shared/ transferred must be in proper FHIR formats defined by ABDM		POST /api/hiecm/consent/v3/request/hip/on-notify
POST /api/hiecm/data-flow/v3/health-information/hip/on-request
/api/hiecm/data-flow/v3/health-information/notify
